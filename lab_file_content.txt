3) Map ER Diagram to Tables

[TYPEWRITTEN SECTION]

1. DEPARTMENT
- Columns:
  - Department_ID INT AUTO_INCREMENT
  - Department_Name VARCHAR(100) UNIQUE NOT NULL
- Primary Key: Department_ID
- Foreign Key: None

2. ADMIN
- Columns:
  - Admin_ID INT AUTO_INCREMENT
  - Name VARCHAR(100) NOT NULL
  - Email VARCHAR(100) UNIQUE NOT NULL
  - Password VARCHAR(255) NOT NULL
- Primary Key: Admin_ID
- Foreign Key: None

3. STUDENT
- Columns:
  - Roll_No VARCHAR(100)
  - Name VARCHAR(100)
  - Email VARCHAR(100) UNIQUE
  - Password VARCHAR(255)
  - Department_ID INT
  - Semester INT
  - CGPA DECIMAL(4,2)
  - Status ENUM('active','inactive','graduated','suspended')
- Primary Key: Roll_No
- Foreign Key: Department_ID -> DEPARTMENT(Department_ID)

4. COURSE
- Columns:
  - Course_ID VARCHAR(20)
  - Course_Name VARCHAR(100)
  - Credits INT
  - Department_ID INT
  - Semester INT
  - Status ENUM('active','inactive','archived')
  - Capacity INT
  - Slot VARCHAR(50)
  - Faculty VARCHAR(255)
  - Course_Type ENUM('core','elective')
  - Elective_Slot VARCHAR(50)
  - Max_Choices INT
- Primary Key: Course_ID
- Foreign Key: Department_ID -> DEPARTMENT(Department_ID)

5. PREFERENCE
- Columns:
  - STUDENT_Roll_No VARCHAR(100)
  - COURSE_Course_ID VARCHAR(20)
  - Rank INT
- Primary Key: (STUDENT_Roll_No, COURSE_Course_ID)
- Foreign Keys:
  - STUDENT_Roll_No -> STUDENT(Roll_No)
  - COURSE_Course_ID -> COURSE(Course_ID)

6. ENROLLMENT
- Columns:
  - STUDENT_Roll_No VARCHAR(100)
  - COURSE_Course_ID VARCHAR(20)
  - Enrollment_Date TIMESTAMP
  - Grade VARCHAR(2)
  - Status ENUM('allotted','waitlisted')
- Primary Key: (STUDENT_Roll_No, COURSE_Course_ID)
- Foreign Keys:
  - STUDENT_Roll_No -> STUDENT(Roll_No)
  - COURSE_Course_ID -> COURSE(Course_ID)

7. ADM_IN_ACCESS
- Columns:
  - ADMIN_Admin_ID INT
  - COURSE_Course_ID VARCHAR(20)
- Primary Key: (ADMIN_Admin_ID, COURSE_Course_ID)
- Foreign Keys:
  - ADMIN_Admin_ID -> ADMIN(Admin_ID)
  - COURSE_Course_ID -> COURSE(Course_ID)

4) Normalization

[HANDWRITTEN SECTION]

- UNF:
  - One large table with repeating course fields per student.
  - Problem: redundancy and many NULL values.

- 1NF:
  - Make all values atomic (no repeating groups).
  - Store preferences and allotments as separate rows.

- 2NF:
  - Remove partial dependency from composite-key tables.
  - Keep student details in STUDENT and course details in COURSE.

- 3NF:
  - Remove transitive dependency.
  - Keep Department_Name only in DEPARTMENT; use Department_ID as FK in STUDENT and COURSE.

- Final result:
  - Schema is in 3NF with less redundancy and better consistency.

B) DML Queries

INSERT INTO STUDENT
(Roll_No, Name, Email, Password, Department_ID, Semester, CGPA, Status)

UPDATE STUDENT
SET CGPA = 9.10
WHERE Roll_No = '23BCS001';

DELETE FROM PREFERENCE
WHERE STUDENT_Roll_No = '23BCS001' AND COURSE_Course_ID = 'CS301';

C) SELECT Queries

WHERE
SELECT Roll_No, Name, CGPA
FROM STUDENT
WHERE Status = 'active' AND Semester = 5;

JOIN
SELECT s.Roll_No, s.Name, c.Course_ID, c.Course_Name, e.Status
FROM ENROLLMENT e
JOIN STUDENT s ON s.Roll_No = e.STUDENT_Roll_No
JOIN COURSE c ON c.Course_ID = e.COURSE_Course_ID;

GROUP BY + ORDER BY
SELECT e.COURSE_Course_ID, COUNT(*) AS total_students
FROM ENROLLMENT e
GROUP BY e.COURSE_Course_ID
ORDER BY total_students DESC;
